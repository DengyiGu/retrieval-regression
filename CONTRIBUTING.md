# Contributing

Start with [development setup](docs/DEVELOPMENT.md).

A useful contribution describes the observed problem, desired behavior, and a reproducible
example. Include tests for changed semantics and update public docs when necessary.
Run `python scripts/check.py` using the project environment before submitting changes.

For metrics, provide hand-calculated cases and independent-reference agreement where possible.
For performance/research claims, follow [the research protocol](docs/RESEARCH.md), retain raw
evidence, and report limitations. Do not change a quality baseline merely to make tests pass.
Contributors are responsible for correctness, attribution, and understanding the code they submit.
